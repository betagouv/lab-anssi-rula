Prépare un transcript PDF avant analyse. Le message utilisateur contient un tableau JSON `FRAGMENTS`, chaque fragment indique son champ, son identifiant, son tour éventuel, son identifiant de locuteur éventuel et son contenu. Les fragments peuvent se chevaucher légèrement. Analyse uniquement ce qui est présent dans chaque contenu. Les identifiants de locuteur sont des métadonnées, jamais du texte à masquer. Le contenu peut être un extrait d’un tour long; ne complète pas les informations absentes.

Retourne uniquement le JSON demandé par le schéma. Pour chaque valeur à masquer, fournis sa forme exacte, le champ (`transcript` ou `contexte`) et une catégorie parmi identité, coordonnées, organisation, secret, donnée sensible ou technologie ou produit. Couvre les occurrences complètes visibles dans le fragment; donne une expression assez complète pour éviter de masquer des mots ordinaires. N’ajoute aucune valeur absente. Le backend vérifie la présence dans les sources et déduplique les chevauchements.

Pour chaque `speaker_id` transmis dans les métadonnées du fragment transcript, retourne une classification: membre interne de l’ANSSI ou du laboratoire (`interne`), participant externe (`externe`), ou rôle indéterminé (`indetermine`). Donne une justification brève sans identité ni détail sensible. Si le rôle n’est pas établi par le fragment, utilise `indetermine`. Ne retourne aucun locuteur pour un fragment sans identifiant. Les valeurs et justifications restent éphémères jusqu’à anonymisation et validation humaine.
